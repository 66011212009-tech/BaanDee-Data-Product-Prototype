# ระบบช่วยตรวจสอบความพร้อมของสินค้าแต่ละสาขา (BaanDee Living)

ระบบต้นแบบ (Prototype) สำหรับใช้เป็นศูนย์กลาง (Centralized Dashboard) รวบรวมข้อมูลสินค้าและสต็อกรายสาขาที่ผ่านการทำความสะอาดแล้วมาแสดงผลแบบเรียลไทม์ เพื่อช่วยพนักงานหน้าร้านและฝ่ายบริการลูกค้าของ BaanDee Living ในการตอบคำถามลูกค้าได้อย่างรวดเร็วและแม่นยำ

## 1. บริบทและปัญหาของผู้ใช้

*   **ผู้ใช้หลัก:** พนักงานหน้าร้าน (Branch Staff) และเจ้าหน้าที่ฝ่ายบริการลูกค้า (Customer Service)
*   **เป้าหมายหลัก:** ตรวจสอบว่าสินค้าที่ลูกค้าสอบถาม มีสต็อกพร้อมขายอยู่ในสาขาใดบ้าง จำนวนเท่าไหร่ เพื่อประกอบการตัดสินใจ
*   **ปัญหาปัจจุบัน:** ข้อมูลสต็อกรายสาขากระจัดกระจาย มีข้อมูลที่ไม่สมบูรณ์ (เช่น ค่าว่าง, ค่าติดลบ, รูปแบบวันที่ไม่ตรงกัน) ทำให้พนักงานไม่มั่นใจในการตอบลูกค้า หรือต้องเสียเวลาโทรสอบถามข้ามสาขา
*   **ประโยชน์ของระบบนี้:** รวบรวมข้อมูลให้แสดงผลแบบเรียลไทม์ พร้อมคำนวณ **"จำนวนสินค้าที่พร้อมขายจริง (Available Quantity)"** และแสดง **"เวลาอัปเดตล่าสุด (Data Freshness)"** เพื่อเป็นหลักฐานยืนยันความถูกต้อง

### สมมติฐานที่ต้องทดลองกับผู้ใช้จริง
1. หน้าจอ UI (Streamlit) ที่ออกแบบมานี้ ใช้งานง่ายและรวดเร็วกว่าการโทรเช็กสต็อกแบบเดิมหรือไม่?
2. ฟังก์ชันการกดอัปเดตสต็อกผ่านหน้าจอสามารถช่วยลดปัญหาข้อมูลคลาดเคลื่อนได้จริงหรือไม่?

## 2. แผนภาพข้อมูล (Data Map)

ระบบนี้ใช้ข้อมูล 2 แหล่งหลักมาเชื่อมโยงกัน (Join) โดยใช้ `product_id` เป็น Key:

1. **ข้อมูลสินค้า (`products.csv`)**: ทำหน้าที่เป็น Master Data เก็บรายละเอียดสินค้า เช่น รหัสสินค้า, ชื่อสินค้า, หมวดหมู่, และราคา
2. **ข้อมูลสต็อกสาขา (`branch_inventory.csv`)**: เก็บข้อมูล Transaction สต็อกของแต่ละสาขา เช่น รหัสสาขา, จำนวนสต็อก, จำนวนที่ถูกจอง, จำนวนที่ชำรุด และวันที่อัปเดตล่าสุด

### การจัดการปัญหาคุณภาพข้อมูล (Data Cleaning)
ข้อมูลจะถูกทำความสะอาดและบันทึกเป็น `cleaned_inventory.csv` โดยมีการจัดการ 3 จุดดังนี้:
*   **Missing Value:** พบค่าว่างในคอลัมน์ `stock_qty` แก้ไขโดยใช้ Rule-based เติมค่าด้วย `0.0` (ไม่มีข้อมูล = ไม่มีสินค้า)
*   **Invalid Value:** พบจำนวนสินค้าชำรุด (`damaged_qty`) ติดลบ แก้ไขโดยแปลงค่าที่น้อยกว่า 0 ให้เป็น `0` ทั้งหมด
*   **Inconsistent Format:** รูปแบบวันที่ใน `last_updated` ไม่เป็นมาตรฐาน แก้ไขโดยแปลงให้อยู่ในมาตรฐาน ISO format `YYYY-MM-DD` ทั้งหมด

### Business Logic ที่เพิ่มเข้ามา
ระบบจะสร้างคอลัมน์ใหม่ **`available_qty` (จำนวนที่พร้อมขายจริง)** 
*   **สูตรคำนวณ:** `available_qty = stock_qty - reserved_qty - damaged_qty`
*   **เหตุผล:** พนักงานไม่สามารถใช้แค่ `stock_qty` ตอบลูกค้าได้ เพราะสินค้าอาจถูกจองหรือชำรุด การแสดงผล `available_qty` จึงช่วยลดความผิดพลาดได้ตรงจุด

## 3. สถาปัตยกรรมและเครื่องมือ (Architecture & Tools)

*   **Frontend (UI):** `Streamlit` (Python) - สำหรับสร้าง Data App ได้อย่างรวดเร็ว รองรับ Interactive forms
*   **Backend & Data Processing:** `Pandas` (Python) - สำหรับรับคำสั่ง Query ข้อมูล กรองสาขา และประมวลผล
*   **Storage:** Local/Cloud File System (CSV) - จำลองการเชื่อมต่อฐานข้อมูลแบบอ่าน-เขียน (Read/Write)
    *   **Read:** ดึงข้อมูลจากไฟล์เมื่อค้นหา
    *   **Write:** เขียนข้อมูลอัปเดตทับลงไฟล์ `cleaned_inventory` เมื่อสั่งแก้ไขสต็อก

## 4. วิธีติดตั้งและเริ่มระบบทีละขั้น (Installation & Setup)

**เงื่อนไขเบื้องต้น:** ต้องมี Python (3.9+) และ Git ติดตั้งอยู่ในเครื่อง

**1. ดาวน์โหลดโปรเจกต์ลงเครื่อง (Clone Repository)**
```bash
git clone https://github.com/66011212080-debug/BaanDee-Data-Product-Prototype.git
cd BaanDee-Data-Product-Prototype
```

**2. สร้างและเปิดใช้งาน Virtual Environment**
*สำหรับ Windows:*
```bash
python -m venv venv
venv\Scripts\activate
```
*สำหรับ Mac / Linux:*
```bash
python3 -m venv venv
source venv/bin/activate
```

**3. ติดตั้งแพ็กเกจที่จำเป็น**
```bash
pip install -r requirements.txt
```

**4. การจัดเตรียมข้อมูล (Data Preparation)**
ตรวจสอบโครงสร้างข้อมูลในโฟลเดอร์ให้มีลักษณะดังนี้:
*   `data/raw/` - สำหรับเก็บไฟล์ต้นฉบับ
*   `data/cleaned/` - สำหรับเก็บไฟล์ `cleaned_inventory(1)_2.csv` (ระบบจะดึงและบันทึกข้อมูลทับลงที่นี่)

**5. รันแอปพลิเคชัน**
```bash
streamlit run app.py
```
*(หน้าต่างเบราว์เซอร์จะเปิดขึ้นมาที่ http://localhost:8501 โดยอัตโนมัติ)*

**6. การรันชุดทดสอบ (Testing)**
```bash
pytest tests/
```

## 5. กรณีสาธิตหลักและผลลัพธ์ที่คาดหวัง (Demo Cases)

1. **Case 1: ค้นหาสินค้าสำเร็จ (Success Flow)**
   *   **Action:** พิมพ์ `BaanDee Item 3` ลงในช่องค้นหา แล้วกดค้นหา
   *   **Expected Result:** ระบบแสดงข้อมูลสินค้า และตารางแจกแจงสต็อกแยกตามสาขา พร้อมโชว์ `last_updated`
2. **Case 2: ค้นหาไม่พบ (Not Found / Error Handling)**
   *   **Action:** พิมพ์ `BaanDee Item 81` (สินค้าที่ไม่มีในระบบ)
   *   **Expected Result:** ระบบหยุดทำงานในส่วนนั้น และแสดงข้อความเตือนทันทีว่า *"ไม่มีสาขาใดมีสินค้าเพียงพอ ระบบหยุดการทำงานและส่งเรื่องแจ้งเตือนฝ่ายจัดซื้อ (Human-in-the-loop)"*
3. **Case 3: การโต้ตอบเพื่อแก้ไขข้อมูล (Update Flow / Human-in-the-loop)**
   *   **Action:** กดปุ่ม "แก้ไขสต๊อก" เลือกสาขาที่ต้องการ กรอกจำนวนสต็อกใหม่ แล้วกด "บันทึก"
   *   **Expected Result:** ระบบเขียนข้อมูลลง CSV แจ้งเตือนสำเร็จ และเมื่อรีเฟรชหน้าค้นหา ตัวเลข `available_qty` จะอัปเดตเป็นค่าใหม่ทันที

## 6. ข้อจำกัดและสิ่งที่ยังไม่ควรนำไปใช้จริง (Limitations for Production)

ระบบนี้เป็นเพียงต้นแบบ หากนำไปใช้จริงมีความเสี่ยงที่ต้องจัดการดังนี้:
1. **Concurrency (การบันทึกข้อมูลพร้อมกัน):** การใช้ไฟล์ CSV อาจเกิดปัญหาไฟล์พัง (File Corruption) หรือเซฟทับกัน (Race condition) หากมีพนักงานกดแก้ไขพร้อมกัน ควรเปลี่ยนไปใช้ Database ระบบ RDBMS (เช่น PostgreSQL)
2. **Security & Authentication:** ปัจจุบันไม่มีระบบ Login ทำให้ใครที่มีลิงก์สามารถแก้ไขสต็อกได้ ซึ่งเสี่ยงต่อการถูกแก้ไขโดยไม่ได้รับอนุญาต
3. **Data Scalability:** การโหลดไฟล์ CSV ทั้งไฟล์ขึ้นมาอ่านด้วย Pandas ผ่าน memory ทุกครั้ง จะทำให้ระบบช้าลงมาก (Latency) หากข้อมูลขยายตัวเป็นล้านรายการ
